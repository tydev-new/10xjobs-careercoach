# Receipts — the incidents that earned the rules

**Why this file exists.** `PRINCIPLES.md` rule 11 requires every behavior to
follow from Part 1 or carry the receipt of a real incident. Goal 4 says where
that receipt lives: *"the commit or the script docstring, not the skill."*
The skills carry the RULE; this ledger carries the HISTORY. An agent reading
a skill does not need to know what went wrong in July — it needs to know what
to do now.

**What stays in the skill anyway.** A *worked example* is instruction, not
history: "collaborated with team" → "stakeholder management across
engineering, operations, and business" invents three departments. That
teaches the boundary of a rule the reader is about to apply. A *date and a
round number* teaches nothing at the moment of use. Keep specimens, move
provenance.

**How to use it.** Re-litigating a rule? Find it here, read what it cost,
then decide. Adding a rule? Add its row here, and put only the rule in the
skill.

**What the review of these two caught, and the lesson.** Four false or
imprecise claims across the two commit messages, including one — "a schema
no checker knew" — that the commit's own receipt refuted, and one invented
rule presented as a relocation. Both cuts also left dangling references that
a literal grep for the deleted name could not see: a section heading spelling
"candidate-market fit" out in full, a routing line naming a mode by
description rather than by file, and an example in the design doc that the
NEXT commit's deletion turned into a dead reference. **Grep the concept, not
the token** — and when a commit deletes a thing, grep the things that thing
was an example OF.
